03 / IN PRACTICE

How people do this today.

Illustrative paths, not prescribed stacks. Teams iterate between steps and use many more tools than shown.

01 / LARGE TEAM

Commercial big-chip flow

  1. Write architecture and RTL in SystemVerilog; run Verible or commercial lint.
  2. Run VCS, Xcelium or Questa regressions; use VC Formal or Jasper for selected properties.
  3. Use Palladium, ZeBu or Veloce to run longer software workloads.
  4. Insert test structures with Tessent; synthesize with Design Compiler or Genus.
  5. Place and route with Fusion Compiler, IC Compiler II or Innovus.
  6. Check timing with PrimeTime or Tempus, power integrity with RedHawk-SC, and DRC/LVS with Calibre using foundry-qualified decks; iterate until signoff.
02 / SMALL TEAM

Mixed-tool startup

  1. Capture interfaces and write RTL; use Verible and Verilator in fast local checks.
  2. Drive simulations with cocotb; use SymbiYosys on suitable properties.
  3. Use commercial simulation or formal tools where project requirements need them.
  4. Prototype on FPGA, then use Yosys and OpenROAD for early exploration or licensed synthesis and physical tools for the target process.
  5. Use appropriate commercial signoff and foundry decks before tapeout; open checks alone are not automatically a substitute.
03 / OPEN SILICON

Student to Tiny Tapeout

  1. Start from the current Tiny Tapeout template and write a small RTL module.
  2. Lint with Verilator and simulate tests with cocotb and a supported simulator.
  3. Use the shuttle’s supported open PDK and OpenLane flow to synthesize with Yosys and implement with OpenROAD.
  4. Inspect layout and checks with tools such as KLayout or Magic; fix reported issues and rerun.
  5. Submit according to the current shuttle instructions. A shared shuttle has submission rules and may have fabrication fees.

04 / QUICK REFERENCE

Words you’ll hear.

EDA
Electronic design automation: software for designing and checking electronics.
RTL
Register-transfer level: a hardware description of state and logic between registers.
PDK
Process design kit: process-specific models, rules and data for designing a chip.
DRC
Design rule checking: tests whether geometry meets specified manufacturing rules.
LVS
Layout versus schematic: checks whether extracted layout connectivity matches the intended circuit.
STA
Static timing analysis: checks timing paths without simulating every input sequence.
DFT
Design for test: adding structures that make manufacturing defects easier to detect.
MPW
Multi-project wafer: a shared fabrication run carrying designs from multiple projects.
GDSII
A common file format for transferring physical layout geometry.
HLS
High-level synthesis: generating RTL from a higher-level algorithmic description.
EM / IR
Electromigration / voltage drop: power-delivery reliability and voltage-loss concerns.
FPGA
Field-programmable gate array: reconfigurable hardware used for prototyping and deployment.

Sources & boundaries.

Each card links to a product page, project documentation, or public reporting. Vendor descriptions establish what is offered, not independent proof of performance or adoption. Examples here are illustrative, not market-share estimates. Pricing is categorized rather than estimated; actual license terms and free tiers change.

AI announcements can describe demos, pilots or planned features rather than broadly deployed products. Verify availability and data handling with the provider; generated designs still need normal engineering review and signoff.
